## 顺带暴露的一个真问题 (不是本 run 的问题, 是实现的)

`ambig-001` 那条 429 是**厂商明说可重试**的突发保护, 却直接把任务打成 `dead_letter`:
`apps/api/app/services/llm_client.py` 的 `ArkLLMClient` 把**任何非 200 一律**
转成 `LLMUnavailable`, 没有退避重试。评测 runner 自己对 API 服务端的 429 是有
退避的 (`evals/runner/client._post_with_backoff`), **模型侧的 429 没有**。

并发 4 + thinking 开的组合最容易撞上它。这是生产路径上的缺口, 不只是评测的:
真实用户在流量尖峰时会看到"模型服务不可用", 而正确行为是退避后重试。
