# 累计花费台账

这份文件还掉"累计花费靠对话记账"这笔债 (SPEC-007 第六节)。每次会真实调用
模型的操作结束后追加一行: 日期 / 操作 / 调用次数 / tokens / 花费 (人民币元) /
配置。**估算口径**: `ai_usage.estimated_cost_cny` 按刊例单价折算, 是估算不是
账单; 与方舟控制台的对账差异也记在这里。

## 基准 (事实与估算分开写, 不混成一个假装是账单的数)

**事实** (方舟控制台, 2026-08-09 读数): **51 次调用 / 188,798 tokens**。
控制台不直接给金额, 金额只能估。

**估算** (两种算法, 假设各自写明):

- 按 token 折算: 假设输入输出 9:1 (agentic 任务输入远大于输出 —— messages 逐轮
  累加、库存清单全文进 prompt), 169,918 × ¥6/M + 18,880 × ¥30/M ≈ **¥1.6**。
  比例换成 8:2 则约 ¥2.0 —— 这个假设值一档就差两毛, 所以它只是量级;
- 按 W4 每次均价线性外推: ¥0.029/次 × 51 ≈ **¥1.48** (均价来自 W4 对话账
  33 次 ¥0.95, 那批以短任务为主, 外推到未知调用同样只是量级)。

**旧口径留底, 已知偏低**: 对话记账 33 次 ¥0.95 (第二段 22 次 ¥0.64 含两次超时
保守入账; 第三段 11 次 ¥0.31; 配置 `doubao-seed-2-1-pro-260628` / prompt v2 /
thinking=disabled / 北京)。与控制台差 18 次 / 约 4.2 万 tokens: 其中一部分是
`scripts/dev/probe_parsing_latency.py` 与冒烟调用没进对话账; 上次读数 (约 45 次 /
14.6 万) 到本次又多 6 次 / 4.2 万 tokens, 而 W5 前两批是零调用 —— **这 6 次
来源未明, 由本人排查** (可能是账号被别处使用, 或本人手动试过)。差额解释完之前,
本台账的"累计"以控制台事实为准。
