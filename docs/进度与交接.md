## 已完成的关键实现（W1）

- **迁移器**（`apps/api/app/db.py`）：API 启动时按序执行 `migrations/*.sql`，
  用 `schema_migrations` 台账保证只跑一次。刻意不走 docker-entrypoint-initdb.d，
  让裸跑 / CI / Docker 三条路径共用同一建表逻辑。W2 起换 Alembic。
- **`/ingest`**：三类事件（sensor_state / heartbeat / rfid_scan）统一入口。
  幂等键 = (device_id, 业务标识, ts)，唯一索引在 `0002_ingest_idempotency.sql`。
  UPSERT 带 `WHERE 旧.ts < 新.ts` 做乱序保护 —— 修复了原 Lambda 无条件覆盖的缺陷。
- **`/status`**：沿用 legacy status-api 的 60s 心跳超时语义，实现下沉到 service 层。
- **device-sim**：YAML 剧本模式 + CSV 真实数据回放模式。数据源是队友仓库导出的
  344 条真实读数（`apps/device-sim/seed/waterlevel_readings.csv`）。
- 测试 24 条全绿（device-sim 6 / policy_engine 5 / api 13）。

- CI 4 条流水线中 **3 条绿**：`api`(带真实 Postgres 跑测试) / `web`(前端构建) / `镜像可构建`

**⚠️ 待修：CI 的 `engine` job 红灯**
- 失败步骤：`.github/workflows/ci.yml` 里的 `ruff check packages apps/api apps/device-sim`
- 性质：**代码风格检查失败，不是功能缺陷**。它挂掉导致后面的 pytest 步骤被跳过。
- 复现不出来：同样命令在开发机上是 `All checks passed`，怀疑是 CI 装的 ruff 版本更新、
  引入了新的默认规则。
- 诊断方法（二选一）：
  1. GitHub Actions 里点失败项的 Details 看报错行
  2. 本机跑 `pip3 install ruff --break-system-packages && ruff check packages apps/api apps/device-sim`
- 修复方向：按报错改代码 + **在 CI 里把 ruff 锁定版本**（`pip install ruff==x.y.z`），
  避免"昨天绿今天红"。工具版本不锁定本身就是该修的工程问题。

## 协作约定

- **git 命令由本人在自己终端执行**，不要让 AI 通过文件桥接跑 git —— 桥接模式下
  AI 无删除权限，会在 `.git/` 里留下 `index.lock` 残留，导致后续 git 报
  `Unable to create '.git/index.lock': File exists`（真遇到就 `rm -f .git/index.lock`）。
- AI 可以直接写文件、改代码；提交和推送本人来。
- 本人不熟悉技术术语，解释请用大白话。
