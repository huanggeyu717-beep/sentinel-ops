## 一、与 SPEC / prompt 不一致的地方 (含需要评审方知道的取舍)

1. **撤端口两条路里选了 `!override` 标签, 没走"ports 挪进 dev 文件"**:
   后者要改基础 `docker-compose.yml`, 而它不在本段可写清单里。前提是
   Compose ≥ v2.24 —— 本机 v5.3.1 与 GitHub runner 都满足, 已写进覆盖层
   注释与 runbook 第一节 (`docker compose version` 是开机检查项)。
   实测不是靠读配置: `docker compose config` 看合并结果 + 起容器后逐个数
   (见第三节变异 5 与第四节)。

2. **`db.py` 的改动越出了"只写 demo_marker 那一行"的字面边界**: 验收还有
   "生产种子里没有 admin 账号"这一条, 所以把种子拆成三段 ——
   `DEV_SEED_SQL` (主体, 无 admin) + `ADMIN_SEED_SQL` (仅非演示库) +
   `DEMO_MARKER_SQL` (仅演示库), 由 `SENTINEL_APPLY_DEMO_MARKER` 一个开关
   切换。**一个开关管两件事** (写通行证 + 不种 admin) 是刻意的: 两件事都是
   "这是公开演示库"的同一判断, 拆两个开关就多一种"写了通行证却带着 admin"
   的错配形态。顺带的收益: 重置脚本 (scripts/ops, 本段冻结) import 的是
   `DEV_SEED_SQL`, 不用改一个字, 每日重置天然不会把 admin 种回演示库。

3. **CI 断言 2 "返回 5 个传感器"实现为 `{1..5} ⊆ 返回的 sensor_id 集合`**:
   `/status/sensors` 实际返回 6 行 (含 0 号占位传感器, 它是前端"未定位"分支
   的种子数据), SPEC 的"5 个"指 5 个在位探头。该接口要登录 (viewer+),
   job 里先用 viewer 演示账号登录 —— 这顺带把"演示账号能登录"也放进了 CI。

4. **docker job 起的是 prod 覆盖层, 不是开发 compose**: SPEC 第四节没指定。
   起 prod 让端口收回、Caddy 反代、SSE 不攒流、1 GiB mem_limit 全部在同一个
   job 里每次 CI 被验 —— 将来部署的正是这套文件与这份镜像 (SPEC 目标 1)。
   代价是 job 需要一个 JWT 密钥: 脚本内置一次性值 (只进即抛容器, 不是秘密)。

5. **SSE "第一个事件 N 秒内到达"以 N=5、零模型调用实现**: psql 裸插一条
   `clarifying` 任务 (非终态, 流不会自己关), `curl -N --max-time 5`,
   断言退出码 28 (= 5 秒后流仍开着被掐断) **且** 输出文件里已有 `event:` 行。
   只断言 200 的话, 攒整条流的反代一样漂亮; 只断言"拿到了事件"的话,
   终态任务推完即关也能骗过 —— 两个断言合起来才等于"流开着的时候事件在冒"。

6. **第 0 件的结算触发面比 prompt 字面更宽一点**: `sweep_once` 对**所有**被
   清扫判死的任务结算 (clarifying 超时、失联、心跳戳缺失三条路), 不只
   clarifying 超时 —— 它们同样是"进终态"。第一段报告第一节第 6 条那"四类
   不回补"就此收窄为: 每日重置清掉在飞任务行的那笔仍不回 (SPEC 已知边界,
   幂等钥匙对不存在的行是 0 行更新, 自然跳过); 进程关停被 cancel 的任务
   重启后由清扫判死时结算, 不再是尾账。

7. **`agent_runtime` 的改动是"提函数 + 一行调用"**: 循环体里 reap + 标弃草稿
   的既有逻辑原样搬进新函数 `sweep_once`, 循环改调它, 再加一行结算。提函数
   不是顺手重构 —— 结算只写在循环体里的话没有测试能守它 ("清扫忘了调结算"
   的变异永远打不红), 见第三节变异 0-a。

8. **Caddy 站点地址走 `{$SENTINEL_SITE_ADDRESS:localhost}`**: 本机验收用
   localhost (内部 CA), 第三段开机器只在 `.env` 加一行域名即可, Caddyfile
   本身一个字不用改; Caddy 对真域名自动转 ACME 真证书。本机验不到真证书这条
   边界照 SPEC 第六节原样写进了 Caddyfile 注释与 runbook。

9. **`test-docker.sh` 用独立 compose project (`-p sentinel-prod-ci`)**:
   收尾的 `down -v` 只删这套自己的卷。不加 -p 的话, 本机跑这脚本会把开发用
   的 pgdata 卷 (sentinel / sentinel_eval 两个库的数据) 连坐删掉。

10. **runbook 把第一段报告第一节第 9 条落了地**: 每日重置的 cron 在重置后
    **重启 api 容器** —— 脚本只管数据库, 引擎内存里已加载的发布策略是陈的。

11. **测试库因旧版 0010 被 DROP 重建**: prompt 说"0010 没有任何库跑过", 但
    sentinel_test 在第一段就跑过它 (没有新列的版本)。0010 未提交, 直接改文件
    是对的; 我把 sentinel_test 整库删掉由 conftest 重建 (它本来就是即抛的)。
    开发库与 eval 库分别停在 0008/0009, 未跑过 0010, 下次启动自动干净升级,
    无需处理。

## 三、变异测试 (第 0 件两条 + SPEC 第九节 4/5, 逐条实跑)

**0-a. 清扫不结算** (删掉 `sweep_once` 里的 `refund_task_hold` 调用):
**3 条红** —— `test_sweep__clarify_timeout_settles_hold` 与
`test_sweep__lease_timeout_...` 红成 `assert 0.6 == 0.0 ± ...` (预扣没回来),
`test_round_end_then_sweep__settles_once` 红在第一轮清扫后台账没动;
`test_settle_twice` 仍绿 (它测幂等不测清扫, 绿是对的)。

**0-b. 每次都回补** (删掉幂等钥匙那两行, 无条件执行 _REFUND):
**3 条红** —— `test_settle_twice__ledger_decreases_only_once` 红成
`assert 0.0 == 0.6 ± 6.0e-07` (第二遍又减了一次);
HTTP 侧 `test_refund__round_end_callback_then_sweep_settle_decreases_once`
同形 (`0.0 == 0.6`) —— **把台账里别人那笔预扣也退掉了**, 这正是"越算越少
直到见底"的起点; `test_sweep__clarify_timeout_settles_hold` 红在
`hold_refunded_at` 仍是 NULL。**值得记录**: 两条双结算用例都刻意在台账里
预置了第二笔 0.6 —— 只放一笔的话, "每次都回补"与正确实现都停在 0.0,
外面看一模一样 (prompt 第 0 件预言的正是这个盲区)。

**4. 删掉 `apps/api/Dockerfile` 里 seed CSV 那行 COPY**: docker job 红在
断言 3, 消息"少了 seed CSV 的 COPY: 容器里每条 Agent 任务都会在 simulating
落 dead_letter", 容器日志随后自动打出。**此变异下 build 全绿、/health 200、
断言 1 通过** —— 旧 job (只 build) 对它完全失明, 这一条是"新 job 真比旧 job
强"的直接证明, W4 那笔债的钉子钉上了。

**5. 覆盖层删掉 db/api 的 `ports: !override []`**: 本机第一跑红在
`Bind for 0.0.0.0:5433 failed: port is already allocated` (开发栈占着 5433,
泄漏的端口当场撞车); 停掉开发库重跑得到 CI 上的真实红形 —— 端口断言
`断言失败: 端口没收干净 (期望恰好 '80 443', 实得 '80 443 5433 8000')`。
两种红形都是同一个事实: 覆写没了, 端口就漏了。

**易错点四的反向验证顺带抓到一个真恒真** (本项目第九次): 第一版验证用
`bytearray(900MB)` 纯分配 —— **exit 0, "限制没生效"**。原因是零页没被写入、
不计 RSS, 与 mem_limit 无关; 改成逐页写 1 字节后 exit 137 (OOM 杀掉),
限制确认是真的。"验证限制的那条命令自己就恒真"已写进覆盖层注释。
