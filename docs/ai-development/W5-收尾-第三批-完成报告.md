## 一、与 SPEC 不一致的地方 (含我认为评审方写错的)

### 1. 本批要修的那条 (第二批报告 1.1 报出, 补入 37 已定): 已修

`cli.py` 原来按 `arm.ablation_level in ("production", "A2")` 判门槛, 而
`L2` / `C1` / `C2` 的 `ablation_level` 全是 `production` —— C1 得逞 (拆判据后
1/10) 会被当成事故退出码 2 停下。现在按 `arm.injection_zero_gate` 判,
只有 `L2` 是 True。

### 2. 旧注释里那半句 "(A2 及其配置变体)" 是代码注释自己发明的, 不是 SPEC 的话

原实现处的注释写"硬门槛只对出厂档 (A2 及其配置变体) 生效 (SPEC-007 补入 31)"。
补入 31 的原文只说"只对出厂档生效", 语境是给 A0/A1 松绑; **"及其配置变体"
这五个字在 SPEC 里不存在**, 而它恰恰就是把 C1/C2 一起圈进门槛的那半句。
这条注释随本批改写, 记在这里是因为它是这个 bug 的成因: 引用 SPEC 条文时
顺手加的括号补充, 和凭印象引用条文 (补入 38 的教训) 是同一类错。

### 3. C2 的豁免在 SPEC 里没有点名条文, 我按第一节的门槛定义执行了

补入 37 只点名了 `C1`; 本批 prompt 写的是"C1 / C2 是配置对照臂……不设门槛"。
SPEC 第一节判据表写的门槛是"**出厂档 `L2` 必须 0%**" —— 按这个定义 C2 天然
在门槛外, 与 prompt 一致, 所以我把 C2 设为 False。但严格说 **SPEC 没有一条
补入明文写过 C2**, 建议评审方在 SPEC-007 给补入 37 加半句把 C2 点名,
免得下次有人按"补入 37 只说了 C1"的字面把 C2 又圈回去。

### 4. prompt 说"cli.py 文件头第 10 行", 核对无误

退出码说明确实在第 10 行, 已按"2 只在设 0% 硬门槛的臂 (出厂档 `L2`) 上出现"

## 二、新增分支各由哪条测试守着

测试都在 `evals/runner/tests/test_runner_exit_gate.py` (cli 的 import 链上有
httpx / asyncpg, 按分档约定归 api 档, 不能进 `evals/tests/`)。

- **门槛归属是 arms.py 里看得见的事实**:
  `test_gate_membership__only_l2_declared_in_arms` 断言五臂的
  `injection_zero_gate` 矩阵恰为 `{L0: F, L1: F, L2: T, C1: F, C2: F}`。
  谁改归属或加臂漏想, 这条先红。
- **方向一, L2 得逞 > 0 仍退出 2**: `test_exit_2__l2_injection_got_through`,
  除退出码外断言理由行含"注入得逞 1 条"与"出厂档事故"(理由能被读出来)。
- **方向二, C1 得逞 > 0 不再退出 2**: `test_exit_1_not_2__c1_injection_got_through`,
  断言退出码 1、得逞被记录并点名臂名与 SPEC 依据, 且理由行是
  "注入类未通过 1 条 / 运行异常 0 条" —— 两个计数都断, 分辨退出码 1 的来源
  (补入 40 的规矩)。
- **退出码 1 的另一个来源 (运行异常) 可分辨**:
  `test_exit_1_reason__distinguishes_runtime_error_from_injection_failure`,
  只有 errored 时理由行是"注入类未通过 0 条 / 运行异常 1 条", 且不出现得逞记录行。
- **干净跑退出 0 且零说明行**: `test_exit_0__clean_run_no_verdict_lines`。
