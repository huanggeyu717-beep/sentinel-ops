### 一、E_BARE_FACT 中文半边换口径 (SPEC 第三节判据 2, 定稿决定 L)

你把单字"分/时"换成两字"分钟/小时"以放行"第一时间""十分明显", 方向对,
但**只修了验收点名的那两个个例, 没有推广**:

- **同形的误伤还在**: "该探头本月第一次报警"、"这是一次跨区派单"、"一次性处置完毕"
  都命中 `一+次`。"第一次"和"第一时间"是同一个形状 (序数「第X」+ 单位);
- **更要紧的是漏拦**: 量词"个"让最自然的中文时长整个漏过 —— "花了两个小时"、
  "半小时后到场"、"一个半小时"、"十来分钟"一条都拦不住。
  **误伤会在 repairing 里暴露出来, 漏拦不会。**

新口径 (SPEC 第三节判据 2 已写死):

- 单位只留**时间与时长**: `分钟 / 小时 / 秒钟 / 秒 / 天`, 去掉 `次 / 条 / 人 / 区 / 级`;
- 数词与单位之间允许**一个约量词**: `个 / 来 / 多 / 余`;
- 数词集合加 `半`;
- **序数「第X」整体放行** (负向后行断言)。

## 易错点

1. 负向后行断言 `(?<!第)` 只挡"第"紧邻的那一个字。"这是第一次"里"第"紧邻"一",
   挡得住; 但别指望它挡"这已经是本月的第 3 次"——那是阿拉伯数字, 由判据 2 前半管;
2. 约量词是**可选一个**, 不是"允许任意字符"。写成 `.{0,1}` 会把"一天多"之类
   拼错的东西也算进去;
3. 改 `_PROPER_NOUN_FACT_IDS` 之后, `test_bare_fact_skips_severity_and_resolved_kind`
   那条必须仍然绿 —— 别把 severity/resolved_kind 顺手一起加进去;
4. 白名单里 `collections.abc` 是**带点的子模块**, 前缀匹配要能容下它;
   `from __future__ import annotations` 不算 import 目标, 但你的扫描器会把它
   收成 `__future__`, 白名单里要么容它要么显式排除 —— **两种都行, 但要有测试钉住
   你选的是哪种**, 别让它碰巧通过。
