## 一、把界面上那句说教删掉

`ApprovalPanel.tsx` 里 `W_NEVER_TRIGGERED` 那段现在是：

> **这条规则在这段历史数据里一次都没命中。**
> 可能是条件写紧了, 也可能是这种情况本来就没发生过。**系统不替你判断 ——
> 数字如实摆在这里, 要不要发布由你来定; 这正是人工审批这一关存在的意义。**

**留前半句，删掉加粗那一整段。**

理由：那句话是**说给面试官听的，不是说给店长听的**。店长盯着警告框想知道的是"这条规则会不会
天天吵我"，不是人工审批的哲学意义。界面上讲设计主张，读起来像系统在替自己辩解。

分工是：**界面说事实，视频和 README 说主张。** 那句话我会搬进视频旁白与文档，
不是不要了，是放错了地方。

（这一句是我在第三段 prompt 里写的，写歪了，不是你的问题。）

顺带检查全站其它文案有没有同类的——**凡是在解释"我们为什么这么设计"的句子，
都不该出现在操作界面上**；解释"这个数字是什么意思、你可以据此做什么"的，留着。

## 二、`btn-ghost` 没有 disabled 样式，"否决"看起来还能点

用 operator 账号打开一条待审批任务，截图里：**批准和发布上线明显置灰，否决看起来是正常按钮。**

查了一下，三个按钮的 `disabled` 条件是对的（否决与批准同一个条件，都是
`!canApprove || !decidable || busy`），**逻辑没问题**——`styles.css` 里
`.btn:disabled` 有 `opacity: 0.5 / cursor: not-allowed`，而 **`.btn-ghost` 根本没有
`:disabled` 规则**，所以它禁用了却看不出来。

补上 `.btn-ghost:disabled`，与 `.btn:disabled` 同一套视觉。**顺手全站扫一遍还有没有
别的 ghost 按钮在禁用状态下没有视觉反馈**（Dashboard 那边也用了这个类）。

这类问题跑测试永远发现不了——按钮点不动是对的，只是人看不出来它点不动。
**只有真的用眼睛看一遍才知道。**

按钮旁边那句"批准与发布需要 manager 及以上角色 (服务端强制, 置灰只是少一个注定 403 的
按钮)"**写得很好，留着**——它说的是事实和后果，不是设计哲学，正是上面第一条要的那种文案。

## 三、补任务列表：审批人现在找不到要批的东西

真人验的时候卡在这：换成 alex 登录后，**根本看不到有哪些任务**。现在只能靠
`/studio?task=N` 这个 URL 直达，`StudioPage.tsx` 的注释也写明了是这个设计。

作为"把工单链接发给人"的机制它没错，**但审批人打开系统应该看见"有几条等我批"**，
而不是等别人把链接发过来。这一屏也是视频里必须有的——**另一个人登录进来、看见一条
等他批**，这个画面比任何功能演示都更能说明"模型没有发布权"。

**后端**：新增 `GET /agent-tasks`，权限与 `GET /agent-tasks/{task_id}` 同档（viewer+）。

- 一条 SQL 出结果，**不要 N+1**（发起人显示名、关联的策略名一起 join 出来）；
- **响应必须有上界**：`limit` 参数带默认值（建议 20，上限 100）。这是本项目立过的规矩
  （SPEC-005 决策 4："内存里的东西必须有上界"），响应体同理；
- 输入文本在列表里**截断**（比如 80 字），别把整段塞进来；
- 支持按 `status` 过滤（列表页要能只看"等审批"）；
- 排序：**未走完的在前**（`clarifying` / `awaiting_approval` / `running`），
  其余按时间倒序。

**前端**：Studio 加一栏任务列表。

- 每条显示：状态徽标、输入文本（截断）、发起人、时间；
- 点一条切过去，**URL 跟着变**（`?task=N`）——直达链接是现有的分享机制，不要废掉；
- `awaiting_approval` 的要一眼看得出来（这是审批人打开页面第一眼要找的东西）。

**列表用 5 秒轮询，不要给它开 SSE。** 你们自己立过这条判断标准（SPEC-005）：
**状态与列表是"看当前值"，用轮询；Agent 执行是"一步步冒出来"的过程，用 SSE。**
给列表开 SSE 是把两件事混了。
